# Historical Image Asset Standard

歴史写真・絵画・錦絵・絵図・古地図・新聞・雑誌・ポスター・史料画像など、公開サイトで使用する図版の選定・表示・権利管理基準。

## 1. 目的

図版は、本文理解を改善し、時代の空間・物質・情報環境を具体化するために使う。単なる雰囲気づくりや空白埋めのためには追加しない。

図版が本文より強く歴史像を規定しうることを踏まえ、「有名だから」「見栄えがするから」だけで採用せず、そのページで何を読み取るための図版かを説明できるものを選ぶ。


### 1.1 年代ページの publication gate

`status: published` の年代ページは、公開前に**図版要否を必ず判定**する。最低1枚を機械的に貼る規則ではなく、次のどちらかを満たす。

- 歴史理解を改善する権利確認済み図版を `src/media/periodFigures.ts` に登録する
- 適切な図版を置かない方がよい場合は、`standards/image-necessity.json` の `noImage` に具体的な理由を記録する

`noImage` は「不要」「候補なし」のような一般論では通さない。本文の中心問いに対して図版が新しい理解を加えない、権利・出典・年代を十分確認できる候補がない、地図・表の方が論点を正確に示す、など、そのページで図版を置かない理由を30字以上で記す。

CIは、published年代ページに図版登録もno-image判定もない状態、図版追加後にno-image判定が残る状態、存在しない年代へのno-image判定を失敗させる。図版を足すこと自体を目的化せず、**「採用」か「理由付き不採用」まで判断したこと**を公開条件とする。


### 1.2 連続 noImage の再監査ゲート

図版候補は人物写真に限らない。条約・外交文書・官報・新聞・雑誌・ポスター・絵図・古地図・統計図表・史料写真など、**本文の中心問いを別の角度から具体化できる一次・同時代資料**も候補に含める。「単一写真では一面を代表しすぎる」という理由だけで、文書・紙面・制度資料まで検討せず `noImage` としてはならない。

published年代ページで `noImage` が **3ページ以上連続**した場合は、通常の個別判定とは別に連続区間を再監査する。CIは `standards/image-necessity.json` の `noImageStreakAudits` に、その連続区間と再検討内容が記録されていない状態を失敗させる。

連続区間の再監査では最低限、次を確認する。

- 人物写真以外に、条約・外交文書・官報・新聞・ポスター・史料画像などを候補化したか
- 各候補が本文のどの中心論点を具体化するか
- 権利、出典、年代、所蔵・提供元を追跡できるか
- 複数ページへ同じ人物写真を機械的に置くより `noImage` の方がよい理由が残るか

`noImageStreakAudits` には対象 `routes`、60字以上の `reason`、実際に検討した候補群を `alternativesReviewed` として2件以上記録する。図版追加で連続状態が解消したら、その監査記録は削除する。これは「図版を必ず置く」規則ではなく、**図版なし判定が自己増殖して資料集としての視覚情報が消えることを防ぐゲート**である。

## 2. 利用できる権利状態

原則として次を優先する。

1. Public Domain / Public Domain Mark
2. CC0
3. CC BY
4. CC BY-SA — 継承条件を確認できる場合のみ

CC BY-NC、CC BY-ND、権利状態が不明な画像、転載条件が個別交渉になっている画像は原則として公開サイトへ追加しない。

「古い作品だから著作権切れ」と推測せず、デジタル複製物を含めて配布元のライセンス表示を確認する。

## 3. provenance

各図版について、少なくとも次を追跡可能にする。

- 作品・資料名
- 制作者または撮影者（不明なら不明とする）
- 制作・撮影年代
- 所蔵・提供機関
- 元ページURL
- ライセンスまたはPublic Domain表示
- 必要な帰属表示
- サイト側で行ったトリミング・色調調整・注記追加などの改変

CC BY / CC BY-SA はライセンス条件に従う帰属表示を必ず出す。Public Domain / CC0 でも出典ページへの導線を原則として表示する。

## 4. 表示

図版には、本文理解に必要な短いキャプションを付ける。キャプションは「何が写っているか」に加え、必要なら「この図版から何を見るのか」を示す。

- 人物写真を装飾的な顔写真一覧にしない
- 史料画像へサイト側の文字を直接焼き込まず、注記は原則HTML側で分離する
- トリミングによって歴史的意味が変わらないか確認する
- object-fitによる切り抜きを使う場合、全体像が必要な史料では避ける
- altは装飾名ではなく、画像を見られない読者にも役割が伝わる内容にする
- スマートフォンでキャプションと出典が読めることを確認する

## 5. 保存・配信

可能なら、権利確認済みファイルをリポジトリまたは管理可能な安定配信先へ置く。外部配信URLを使う場合は、公共機関・博物館・Wikimedia Commonsなど継続性と出典確認性の高い提供元を優先する。

PDF・DjVuなどの文書ファイルは、Commonsのファイル本体URLや `Special:Redirect/file` がそのまま `<img>` で表示できる画像を返すとは限らない。文書の1ページ目を図版として使う場合は、実際に画像として表示できるプレビューURLを確認してから登録するか、権利条件を満たす派生画像を管理可能な配信先へ保存する。出典導線は元の文書ページへ残す。

外部画像が読み込めなくても本文理解が破綻しない構成にする。画像は補助資料であり、本文の歴史的主張を画像だけへ委ねない。

## 6. デザイン

公開面は教科書・資料集の編集デザインを基本とする。図版は十分な余白、明瞭なキャプション、本文との視覚的な関係を持たせる。

品質目標としては Awwwards / Webby Awards / FWA 等で評価されるサイトに匹敵するタイポグラフィ、余白、情報階層、レスポンシブ品質、アクセシビリティ、細部の完成度を目指す。ただし、それらの表層的な派手さ、巨大見出し、過剰なスクロール演出、本文を阻害するアニメーションは模倣しない。

評価基準は「歴史資料を読みたくなる」「長文を読み続けられる」「図版と本文の関係が明瞭」「PC / mobileで破綻しない」である。
