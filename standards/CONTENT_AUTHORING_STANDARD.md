# Content Authoring Standard

日本史本文・年代ページ・用語集・出典・内部リンクの詳細規約。

## 1. 歴史記述

歴史を結果から逆算しない。各時点で、当時確認できた事実、同時代人の情報・認識、当時存在した選択肢・制約、後世から確認できる結果、研究上の解釈を区別する。

重要事件は「事件 → 直接背景 → 制度・経済・社会条件 → 長期構造 → 変化したもの → 残ったもの」を意識する。ただし前後関係だけで因果を断定しない。

「鎖国＝完全な断絶」「士農工商＝社会全体を四身分に完全分割」「1868年に近代国家が完成」など、便利な一語で複雑な実態を潰さない。

### 1.1 主張層と留保層を分ける

正確さのための留保が、本文の主線を隠してはならない。年代ページでは、**主張を述べる場所**と**読み方の留保を置く場所**を明示的に分ける。

本文・summary・snapshot・changes は「主張層」とする。まず、その時期に成立していた状態、変化した仕組み、主要な因果関係を肯定文で示す。各主要節は原則として **状態・変化 → 仕組み → 帰結** の順で組み立て、「何ではないか」を積み上げて結論へ近づかない。

`contemporaryAssumptions` は **「当時の前提」** として、その時点で政策主体・住民・制度を拘束していた制度、情報、技術、地理、財政、社会条件を肯定文で置く。\n\n`interpretiveCautions` は **「読み方の留保」** として、後知恵、単純化、用語の過剰一般化、後年の結果からの逆算など、読者の誤読を防ぐ一般的な注意を集約する。

本文中の否定・限定は次の3種に分けて扱う。

1. **それ自体が歴史的事実である境界**  
   例：条約がまだ発効していない、制度上の権限が別機関に属する、法的地位が異なる。これは本文に置いてよい。ただし可能なら「AはXを担当し、BはYを担当した」のように肯定形で書く。
2. **その節の因果理解に不可欠な局所的な限界**  
   主張を示した後に一度だけ置く。段落の中心を留保にしない。
3. **一般的な誤読防止・反後知恵**  
   「〜を意味しない」「〜と同一視しない」「〜だけで説明しない」「後の結果から逆算しない」などは原則として `interpretiveCautions` へ移し、本文では反復しない。

追加ルール：

- 段落や節を「ただし」「しかし」「〜ではない」「〜と同一視できない」から始めることを常態化しない。
- summary・見出し・changes.significance は、とくに肯定的な状態記述を優先する。見出しを「何ではないか」で作るのは、法的・制度的な区別そのものが中心論点の場合に限る。
- 同じ誤読防止を本文と `interpretiveCautions` の両方へ重複して書かない。**一つの留保は原則一か所**に置く。
- 「Aではない。Bでもない。」より「AによってBが変わった。Cは残った。」を優先する。
- 「〜を理解するには」「〜を見る／読む／捉える必要がある」「〜と読むと見えにくい」「〜とまとめると実態を失う」のように、**読者の解釈方法を指示・矯正するメタ文も留保機能**として扱う。一般的な誤読防止なら `interpretiveCautions` へ移し、本文では「主体・制度・条件・結果」を直接述べる。
- 当事者自身が「〜する必要がある」と述べた、相手側の「誤解」を解こうとした、などの発言・認識そのものは歴史的事実なので上記メタ文と区別する。誰の認識・発言かを明示して本文へ置いてよい。
- 留保を削るために史実の不確実性、研究上の対立、地域差、制度上の例外を消してはならない。必要な留保を、主張の文章から分離して見通しよく置くことが目的である。

レビューでは、本文だけを続けて読んだときに「何が起き、何が変わったか」が先に理解できること、留保欄だけを読んだときに「どの誤読を避けるべきか」が分かることを確認する。さらに公開前に `interpretiveCautions` を1項ずつ summary・snapshot・changes・本文と意味単位で突き合わせる。同じ内容が両方にある場合は、主要な歴史的主張・因果なら主張層へ残して留保側を削除し、一般的な誤読防止なら留保側へ残して主張層から削除する。言い換えただけの重複を両方に残さない。

CIでは、主張層に「意味しない」「同一視しない」「わけではない／なく／なかった」「同じではない」「ことではない」「〜したのではない」「単なる〜ではない」「〜だけの〜ではない」「別々の〜ではない」「一方的に〜ではなく」「〜だけでは〜できない／足りない」「みなさない」「〜だけで／だけから説明しない」「〜と考えると…誤る」に加え、「理解するには〜必要」「〜を見る／読む／捉える必要がある」「〜と読む／まとめると見えにくい・単純化する」など、**語彙を言い換えても機能が読者向けの誤読防止になっている表現**を検査する。該当表現が歴史的事実の境界として本文に不可欠な場合だけ、直前に理由付き例外コメントを置く。YAMLでは `# claim-caution-lint: allow reason="理由"`、Markdown本文では `<!-- claim-caution-lint: allow reason="理由" -->` を使う。理由のない抑制やファイル単位の一括除外は禁止する。

さらに「ではない」「ではなかった」「とは限らない」「とは考えにくい」「そうとも言い切れない」「単純化できない」「必要はない」の反復を、記事単位の**否定フレーミング密度**として検査する。対象は summary / snapshot / changes / Markdown本文などの主張層とし、8件以上かつ対象文字1,000字あたり0.8件以上ならCIを失敗させる。条約未発効、権限差、制度上の非同一性などを明示するための囲み情報まで機械的に抑制しないため、`contemporaryAssumptions`（当時の前提）と `interpretiveCautions`（読み方の留保）は密度の件数・分母の双方から除外する。sources / nextIssues / maps 等の非主張メタデータ、引用ブロック、コードブロックも数えない。理由付き `claim-caution-lint` 例外を付けた直後の文も密度から除外する。

## 2. 史実・数値・出典

特に日付、人数、人口、石高、物価、生産量、死傷者、予算、法令施行時期、条約、引用、地理的位置、境界、行政区分は確認する。

### 2.1 暦・日付表記

1872年以前の月日は、当時の太陰太陽暦とグレゴリオ暦を無表示で混在させない。

- 年だけを示す場合は西暦年でよい。
- 旧暦の月日を示す場合は元号を伴って明示し、時系列理解に重要な日付は、確認できる場合にグレゴリオ暦換算も併記する。
- 西暦の月日を示す場合は、換算後のグレゴリオ暦日付であることを確認する。
- 同じ節・表の中で、旧暦の月日と換算西暦の月日を区別なく並べない。
- 出典が片方の日付しか示さず、換算を確認できない場合は推測で補わない。


情報源の優先順位：
1. 一次史料・公文書・法令・公的統計
2. 国立公文書館、国立国会図書館、JACAR、大学、博物館、研究機関
3. 査読論文・学術書
4. 信頼できる概説
5. 補助的二次情報

Wikipedia等は入口には使えても重要主張の最終根拠にしない。未確認の書名・URL・ページ番号を作らない。

数値は対象年、地域、単位、名目/実質、推計/実測、集計定義、出典を可能な限り確認する。江戸期などは偽の精密さを避ける。史料本文、統計からの観察、研究者の解釈、本サイトの整理を混同しない。

## 3. 年代ページの本文

必要テーマだけに比重を置き、網羅目的で関係の薄い節を増やさない。

本文は教科書風の平明な文章とし、「ここでは確認する」「今後追加する」などの編集メモを公開文章にしない。公開面に draft/review/published、TODO、未実装候補、企画書、CI、実装履歴を出さない。史実の不確実性や史料上必要な注記は読者向け情報として公開してよい。

主対象は、日本史を教養として体系的に読みたい読者とし、年齢や所属は限定しない。文章の難易度と説明の組み立ては、**高校生が無理なく読み進め、本文だけで「誰が何をし、何が変わったか」を追える水準**を基準とする。前提知識は**中学校の歴史教科書レベル**とし、高校日本史で詳しく扱う制度・人物・事件・用語は、初出時または理解に必要な最初の箇所で役割・位置づけを本文中に補う。内容の到達点は下げず、結果として大学入試の論述・記述の整理にも利用できる水準を目指す。ただし、受験テクニック、頻出度、暗記優先度を本文やUIの中心には置かない。

### 3.1 本文厚み監査 — 文字数はシグナルであり、執筆目標ではない

`status: published` の年代ページは、frontmatter の `changes`・`contemporaryAssumptions`・`interpretiveCautions` 等とは別に、Markdown本文だけで中心となる状態遷移を追えるようにする。本文量の判定は、**何字あるかより、前ページから何が変わったかを新しい情報として説明できているか**を優先する。

CIでは実質本文文字数を計測するが、役割を二段階に分ける。

- **4,500字未満：soft review threshold**。警告のみとし、CIを失敗させない。短いこと自体を理由に増補しない。
- **2,500字未満：hard floor**。骨組みだけの公開を防ぐ安全網として、原則CIを失敗させる。ただし対象期間・論点が狭く、必要な状態・仕組み・帰結が2,500字未満で閉じる場合は理由付き例外を認める。
- **4,500字以上：合格証ではない**。同じ因果の言い換え、前ページの再説明、summary等の再掲で到達しても品質上の加点にはならない。

歴史的に説明すべき内容が残っている場合は、次の不足を補う。

- 誰が何を決め、どの制度・権限で実行したか
- その選択を制約した財政、兵站、資源、情報速度、地理、外交関係
- 制度変更が政府・軍・企業・労働者・地域社会・住民の負担や選択肢をどう変えたか
- 前段の状態から何が変わり、その変化が次の状態を何によって可能・困難にしたか
- 高校日本史で初出となる制度・人物・法令を、本文だけで因果まで追える最小限の説明

一方、**本文量を増やすための反復は禁止する**。追加段落は原則として、既存段落にない **主体・仕組み・制約・帰結・史料上の根拠** の少なくとも一つを増やす。次は増補として数えない。

- summary / snapshot / changes / contemporaryAssumptions / interpretiveCautions の言い換えコピー
- 同じ因果関係や結論を、語順だけ変えて複数回説明すること
- 隣接年代で説明済みの背景を、新しい状態変化に必要な範囲を超えて再掲すること
- 用語集リンクで足りる一般定義を長文化すること
- 中心問いに寄与しない出来事や人物を文字数確保のため追加すること
- 根拠の弱い一般論、推測、後知恵を説明量の穴埋めに使うこと
- 節末・記事末で直前数節の出来事をもう一度時系列に並べ直すこと

隣接年代との接続では、前ページの終点を**1〜2文の前提**として受け、原則として新ページ固有の差分へ直ちに入る。前ページの制度説明・交渉条件・会議手順などを再掲する必要がある場合は、その情報が新ページで別の因果的役割を持つことを確認する。

記事末の「この時点の状態」節は置いてよいが、本文の再要約欄にはしない。**開始時点から変わった状態、まだ残った制約、次ページへ渡す未解決点**に絞り、本文で説明済みの出来事を再列挙しない。

2,500字未満でも内容が閉じている場合だけ、Markdown本文へ次の非表示コメントを置く。

```html
<!-- body-depth-audit: allow reason="なぜ2,500字未満で完結するのかを具体的に書く" coverage="どの主要因果・制度・負担・次ページへの接続まで説明済みで、何を足すと重複・希薄化するのかを書く" -->
```

`reason` は30字以上、`coverage` は40字以上を必須とする。「期間が短い」「十分だから」のような一般論だけでは通さない。2,500字以上になったページに例外コメントが残っている場合もCIで失敗させる。

CIは同一ページ内の長い段落の完全重複を失敗させる。さらに隣接年代の長段落類似度を `validate:period-repetition` で検査し、中程度の類似はレビュー警告、ほぼコピーに近い類似は失敗とする。意味的な言い換え反復は機械判定だけに委ねず、レビューで「追加段落が新しい主体・仕組み・制約・帰結・根拠のいずれかを増やしたか」を確認する。

### 3.2 高校生が無理なく読める文章、前提知識は中学歴史

読み手が高校日本史の用語体系を既に知っていることを前提にしない。

- 高校日本史で初めて詳しく扱う制度・役職・政治勢力・法令・条約・金融用語などは、初出時に「何をする仕組み／主体か」を1文で説明してから議論を進める。本文だけでなく、ページ冒頭の summary / snapshot / changes / framingQuestion も同じ基準で書く。
- 人物名だけで説明を進めず、その場で重要な役割を短く添える。例：「元老の一人で首相選定にも影響した山県有朋」のように、本文理解に必要な役割を示す。
- 事件名・法令名を知識の圧縮記号として使わない。「何が起き、何が変わった制度・事件か」を本文で読めるようにする。
- 「元老」「藩閥」「政友会」「貴族院」「枢密院」「統監府」「総督府」「金本位制」「公債」など、用語集リンクがあっても本文の因果を追うために必要な意味は本文側にも残す。
- 中学教科書で扱う語でも、サイト上の中心論点に直結する場合は再説明してよい。
- 易しくするために史実・制度差・論争点を削らない。説明の階段を追加し、最終的な分析水準は維持する。
- 1文の補足で足りる概念に長い基礎講座を挿入しない。本文の主線を止めずに、初見読者が次の文を理解できる最小限の足場を置く。
- 「制度回路」「調整構造」「政策枠組み」「既成事実」「統制」などの抽象語を、具体的な主体・行為・結果の説明より先に置かない。必要なら先に「政府が何を決めたか」「軍がどこで何をしたか」「議会や省庁が何を担当したか」を述べ、その後で抽象化する。
- summary / framingQuestion / 各節冒頭では、固有名詞や法令名を列挙するだけで済ませず、初見の高校生が「このページで何が問題なのか」を一読で把握できる文にする。
- 一文に複数の制度・人物・地域・因果関係を詰め込みすぎない。読み返さないと主語・動作・結果が分からない文は分割する。

レビュー時は「用語リンクを開かなければ主文の意味が取れない」「人物名・制度名を知っている前提で因果が省略されている」「事件名を覚えている前提で変化内容を省略している」箇所を修正対象とする。

### 3.3 隣接年代の接続はページ実装のDoDに含める

新しい年代ページを `published` にする前に、直前年代との境界を同じ実装作業内で確認する。

最低限、次を確認する。

- 直前ページの `nextIssues` や末尾で残した構造的論点が、新ページの冒頭・中心問い・本文へ自然に接続している
- `changes` の `before` が直前ページの実態と矛盾していない
- 同じ説明を両ページで重複させず、前ページは前提、新ページは状態変化として役割分担できている
- 境界をまたいだ因果の飛躍、制度の突然の消失・出現、後世の結果からの逆算がない
- 政治・経済・社会・外交など、前ページで重要だった制約を理由なく消していない

この確認は年代ページの完成条件であり、公開直後に同じ境界を再確認するだけの独立した「接続監査」を置かない。

独立した横断監査を行うのは、複数年代・複数記事をまとめて見ないと発見しにくい長期的な重複、概念のずれ、全体構成上の一本道化、横断記事との役割重複などが対象の場合に限る。

## 4. 横断コンテンツの必要性

構造史・テーマ史などの横断記事は、年代ページの要約集として作らない。

公開候補には、実装前に次を確認する。

- 年代ページとは異なる中心問いがある
- 複数年代を比較しなければ見えにくい制度・権限・負担・情報・資金などの構造を説明できる
- 年代記事の段落を並べ替えるだけでは成立しない
- 既存の横断記事を延長するだけで解決できない

これらを満たさない場合は、新規記事を作らず、年代記事間の内部リンク、比較表、既存記事の期間延長などを優先する。

横断記事で年代上の出来事を再掲する場合も、再掲自体を目的にせず、共通の比較軸へ変換する。候補数や計画上の連番を埋めることを完成条件にしない。

### 4.1 既存横断記事の延長と分割

既存の横断記事は、新しい年代ページと関連するという理由だけで自動延長しない。延長するのは、**新しい年代の状態が、その記事の既存の中心問いへの答えを実質的に変える場合**に限る。

- 同じ用語・制度・主体が再登場しただけなら、年代記事から既存横断記事へリンクするだけでよい。
- 新しい年代を加えることで framingQuestion に独立した問いを継ぎ足す必要が生じる場合は、延長より分割を優先する。
- 分割境界は年数や relatedPeriods 数で機械的に決めず、中心問い、制度主体、比較軸が変わる地点に置く。
- 100年を扱っても一つの問いで閉じる記事は許容し、10年でも独立した問いが複数あるなら分ける。
- 分割後の記事は内部リンクで接続できるが、最初の記事から順番に読まなければ理解できない「第二の通史」にはしない。
- 年代記事・既存テーマ史へ責務を委ねられる説明は重複して抱えず、横断記事固有の比較軸へ絞る。

## 5. 重要用語

用語の定義は年代ごとに複製せず、`content/glossary/terms.json` の全体辞書で一意に管理する。各用語は最低限 `id`, `term`, `category`, `definition`, `connections` を持つ。`connections` には、その語を他の制度・社会構造・出来事とどう結びつけて理解するかを書く。

各年代は `content/glossary/periods/<routeKey>.json` で用語IDを参照する。年代側は最低限 `id`, `core` を持ち、その年代に固有の補足が必要な場合だけ `periodNote` を持たせる。

構造史・テーマ史などの横断記事は `content/glossary/crosscutting/<routeKey>.json` で同じ全体辞書を参照する。横断記事でも用語定義を複製せず、本文から `[[term:<id>|表示語]]` で記事内の用語欄へリンクする。`core: true` は入試上の必須度ではなく、その年代を理解するうえで本文から明示リンクすべき中核語を表す。

本文からの明示リンク記法：

```text
[[term:<id>|表示語]]
```

同じ語の全出現を機械的にリンクせず、説明上重要な箇所だけリンクする。年代をまたいで同じ語が登場しても定義は共通辞書を再利用し、年代ページでは必要な語だけ再掲する。

CIでは、全体辞書のID重複・不正ID・必須項目欠落、存在しない用語IDへの年代参照、年代内の参照重複、本文リンク先の不存在、本文リンクが年代参照に含まれない状態、`core` 用語の本文未使用を検査する。

用語数・年代数が増えても総当たりを行わない。全体辞書を一度だけIDインデックスへ読み込み、各年代原稿と年代参照ファイルを一度ずつ処理する線形走査を基本とする。

## 6. 内部リンク

年代・用語・テーマ・構造史などの内部リンクは可能な限りIDベースで管理し、リンク先の存在をCIで検査できる構造にする。Markdown compiler移行後も参照先IDの解決をbuild前validationへ含める。

## 7. 公開デザイン

基本は教科書・資料集風。本文は明朝系、見出し・ナビ・表見出しはゴシック系。落ち着いた配色、長文を読みやすい行長・行間を優先し、過度な英字ラベル、巨大見出し、ゲームUI・管理画面風表現を避ける。PC / mobileの両方で可読性を確認する。
