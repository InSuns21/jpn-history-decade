# Content Authoring Standard

日本史本文・年代ページ・用語集・出典・内部リンクの詳細規約。

## 1. 歴史記述

歴史を結果から逆算しない。各時点で、当時確認できた事実、同時代人の情報・認識、当時存在した選択肢・制約、後世から確認できる結果、研究上の解釈を区別する。

重要事件は「事件 → 直接背景 → 制度・経済・社会条件 → 長期構造 → 変化したもの → 残ったもの」を意識する。ただし前後関係だけで因果を断定しない。

「鎖国＝完全な断絶」「士農工商＝社会全体を四身分に完全分割」「1868年に近代国家が完成」など、便利な一語で複雑な実態を潰さない。

### 1.1 主張層と留保層を分ける

正確さのための留保が、本文の主線を隠してはならない。年代ページでは、**主張を述べる場所**と**読み方の留保を置く場所**を明示的に分ける。

本文・summary・snapshot・changes は「主張層」とする。まず、その時期に成立していた状態、変化した仕組み、主要な因果関係を肯定文で示す。各主要節は原則として **状態・変化 → 仕組み → 帰結** の順で組み立て、「何ではないか」を積み上げて結論へ近づかない。

`contemporaryAssumptions` は内部フィールド名を維持するが、公開面では **「読み方の留保」** として扱う。後知恵、単純化、用語の過剰一般化、後年の結果からの逆算など、読者の誤読を防ぐ一般的な注意はここへ集約する。

本文中の否定・限定は次の3種に分けて扱う。

1. **それ自体が歴史的事実である境界**  
   例：条約がまだ発効していない、制度上の権限が別機関に属する、法的地位が異なる。これは本文に置いてよい。ただし可能なら「AはXを担当し、BはYを担当した」のように肯定形で書く。
2. **その節の因果理解に不可欠な局所的な限界**  
   主張を示した後に一度だけ置く。段落の中心を留保にしない。
3. **一般的な誤読防止・反後知恵**  
   「〜を意味しない」「〜と同一視しない」「〜だけで説明しない」「後の結果から逆算しない」などは原則として「読み方の留保」へ移し、本文では反復しない。

追加ルール：

- 段落や節を「ただし」「しかし」「〜ではない」「〜と同一視できない」から始めることを常態化しない。
- summary・見出し・changes.significance は、とくに肯定的な状態記述を優先する。見出しを「何ではないか」で作るのは、法的・制度的な区別そのものが中心論点の場合に限る。
- 同じ誤読防止を本文と「読み方の留保」の両方へ重複して書かない。**一つの留保は原則一か所**に置く。
- 「Aではない。Bでもない。」より「AによってBが変わった。Cは残った。」を優先する。
- 留保を削るために史実の不確実性、研究上の対立、地域差、制度上の例外を消してはならない。必要な留保を、主張の文章から分離して見通しよく置くことが目的である。

レビューでは、本文だけを続けて読んだときに「何が起き、何が変わったか」が先に理解できること、留保欄だけを読んだときに「どの誤読を避けるべきか」が分かることを確認する。

## 2. 史実・数値・出典

特に日付、人数、人口、石高、物価、生産量、死傷者、予算、法令施行時期、条約、引用、地理的位置、境界、行政区分は確認する。

### 2.1 暦・日付表記

1872年以前の月日は、当時の太陰太陽暦とグレゴリオ暦を無表示で混在させない。

- 年だけを示す場合は西暦年でよい。
- 旧暦の月日を示す場合は元号を伴って明示し、時系列理解に重要な日付は、確認できる場合にグレゴリオ暦換算も併記する。
- 西暦の月日を示す場合は、換算後のグレゴリオ暦日付であることを確認する。
- 同じ節・表の中で、旧暦の月日と換算西暦の月日を区別なく並べない。
- 出典が片方の日付しか示さず、換算を確認できない場合は推測で補わない。


情報源の優先順位：
1. 一次史料・公文書・法令・公的統計
2. 国立公文書館、国立国会図書館、JACAR、大学、博物館、研究機関
3. 査読論文・学術書
4. 信頼できる概説
5. 補助的二次情報

Wikipedia等は入口には使えても重要主張の最終根拠にしない。未確認の書名・URL・ページ番号を作らない。

数値は対象年、地域、単位、名目/実質、推計/実測、集計定義、出典を可能な限り確認する。江戸期などは偽の精密さを避ける。史料本文、統計からの観察、研究者の解釈、本サイトの整理を混同しない。

## 3. 年代ページの本文

必要テーマだけに比重を置き、網羅目的で関係の薄い節を増やさない。

本文は教科書風の平明な文章とし、「ここでは確認する」「今後追加する」などの編集メモを公開文章にしない。公開面に draft/review/published、TODO、未実装候補、企画書、CI、実装履歴を出さない。史実の不確実性や史料上必要な注記は読者向け情報として公開してよい。

主対象は、日本史を教養として体系的に読みたい読者とする。前提知識は**中学校の歴史教科書レベル**とし、高校日本史で詳しく扱う制度・人物・事件・用語は、初出時または理解に必要な最初の箇所で役割・位置づけを本文中に補う。内容の到達点は下げず、結果として大学入試の論述・記述の整理にも利用できる水準を目指す。ただし、受験テクニック、頻出度、暗記優先度を本文やUIの中心には置かない。

### 3.2 前提知識は中学歴史、到達点は下げない

読み手が高校日本史の用語体系を既に知っていることを前提にしない。

- 高校日本史で初めて詳しく扱う制度・役職・政治勢力・法令・条約・金融用語などは、初出時に「何をする仕組み／主体か」を1文で説明してから議論を進める。本文だけでなく、ページ冒頭の summary / snapshot / changes / framingQuestion も同じ基準で書く。
- 人物名だけで説明を進めず、その場で重要な役割を短く添える。例：「元老の一人で首相選定にも影響した山県有朋」のように、本文理解に必要な役割を示す。
- 事件名・法令名を知識の圧縮記号として使わない。「何が起き、何が変わった制度・事件か」を本文で読めるようにする。
- 「元老」「藩閥」「政友会」「貴族院」「枢密院」「統監府」「総督府」「金本位制」「公債」など、用語集リンクがあっても本文の因果を追うために必要な意味は本文側にも残す。
- 中学教科書で扱う語でも、サイト上の中心論点に直結する場合は再説明してよい。
- 易しくするために史実・制度差・論争点を削らない。説明の階段を追加し、最終的な分析水準は維持する。
- 1文の補足で足りる概念に長い基礎講座を挿入しない。本文の主線を止めずに、初見読者が次の文を理解できる最小限の足場を置く。

レビュー時は「用語リンクを開かなければ主文の意味が取れない」「人物名・制度名を知っている前提で因果が省略されている」「事件名を覚えている前提で変化内容を省略している」箇所を修正対象とする。

### 3.1 隣接年代の接続はページ実装のDoDに含める

新しい年代ページを `published` にする前に、直前年代との境界を同じ実装作業内で確認する。

最低限、次を確認する。

- 直前ページの `nextIssues` や末尾で残した構造的論点が、新ページの冒頭・中心問い・本文へ自然に接続している
- `changes` の `before` が直前ページの実態と矛盾していない
- 同じ説明を両ページで重複させず、前ページは前提、新ページは状態変化として役割分担できている
- 境界をまたいだ因果の飛躍、制度の突然の消失・出現、後世の結果からの逆算がない
- 政治・経済・社会・外交など、前ページで重要だった制約を理由なく消していない

この確認は年代ページの完成条件であり、公開直後に同じ境界を再確認するだけの独立した「接続監査」を置かない。

独立した横断監査を行うのは、複数年代・複数記事をまとめて見ないと発見しにくい長期的な重複、概念のずれ、全体構成上の一本道化、横断記事との役割重複などが対象の場合に限る。

## 4. 横断コンテンツの必要性

構造史・テーマ史などの横断記事は、年代ページの要約集として作らない。

公開候補には、実装前に次を確認する。

- 年代ページとは異なる中心問いがある
- 複数年代を比較しなければ見えにくい制度・権限・負担・情報・資金などの構造を説明できる
- 年代記事の段落を並べ替えるだけでは成立しない
- 既存の横断記事を延長するだけで解決できない

これらを満たさない場合は、新規記事を作らず、年代記事間の内部リンク、比較表、既存記事の期間延長などを優先する。

横断記事で年代上の出来事を再掲する場合も、再掲自体を目的にせず、共通の比較軸へ変換する。候補数や計画上の連番を埋めることを完成条件にしない。

## 5. 重要用語

用語の定義は年代ごとに複製せず、`content/glossary/terms.json` の全体辞書で一意に管理する。各用語は最低限 `id`, `term`, `category`, `definition`, `connections` を持つ。`connections` には、その語を他の制度・社会構造・出来事とどう結びつけて理解するかを書く。

各年代は `content/glossary/periods/<routeKey>.json` で用語IDを参照する。年代側は最低限 `id`, `core` を持ち、その年代に固有の補足が必要な場合だけ `periodNote` を持たせる。

構造史・テーマ史などの横断記事は `content/glossary/crosscutting/<routeKey>.json` で同じ全体辞書を参照する。横断記事でも用語定義を複製せず、本文から `[[term:<id>|表示語]]` で記事内の用語欄へリンクする。`core: true` は入試上の必須度ではなく、その年代を理解するうえで本文から明示リンクすべき中核語を表す。

本文からの明示リンク記法：

```text
[[term:<id>|表示語]]
```

同じ語の全出現を機械的にリンクせず、説明上重要な箇所だけリンクする。年代をまたいで同じ語が登場しても定義は共通辞書を再利用し、年代ページでは必要な語だけ再掲する。

CIでは、全体辞書のID重複・不正ID・必須項目欠落、存在しない用語IDへの年代参照、年代内の参照重複、本文リンク先の不存在、本文リンクが年代参照に含まれない状態、`core` 用語の本文未使用を検査する。

用語数・年代数が増えても総当たりを行わない。全体辞書を一度だけIDインデックスへ読み込み、各年代原稿と年代参照ファイルを一度ずつ処理する線形走査を基本とする。

## 6. 内部リンク

年代・用語・テーマ・構造史などの内部リンクは可能な限りIDベースで管理し、リンク先の存在をCIで検査できる構造にする。Markdown compiler移行後も参照先IDの解決をbuild前validationへ含める。

## 7. 公開デザイン

基本は教科書・資料集風。本文は明朝系、見出し・ナビ・表見出しはゴシック系。落ち着いた配色、長文を読みやすい行長・行間を優先し、過度な英字ラベル、巨大見出し、ゲームUI・管理画面風表現を避ける。PC / mobileの両方で可読性を確認する。
