# 1941年後半 高校生可読性監査

## 目的

「高校生が無理なく読み進め、本文だけで誰が何をし、何が変わったかを追える」という基準が、実際の公開本文で守られているかを確認する。難しい歴史用語を減らす監査ではなく、**正確な内容を保ったまま認知負荷を下げられているか**を対象とする。

## 対象

- 1941-07-03 〜 1941-12-08 の年代記事23本
- 本文を中心に、summary・見出し・framingQuestionも確認
- 1941年後半は日米交渉、国策再検討、開戦準備が短い周期で進み、制度・外交・軍事の説明が密になるため、可読性基準の検証対象として適している

## 方法

全23記事を横断し、次を人間レビューした。

1. 主語・行為・結果を一読で追えるか
2. 初見の制度名・人物名が説明なしに因果の圧縮記号になっていないか
3. 「構造」「枠組み」「回路」「分岐」「意思決定」などの分析語が、具体説明より先に置かれていないか
4. 一文へ複数の主体・制度・条件・因果を詰め込みすぎていないか
5. 見出し・段落冒頭だけを追っても出来事の流れが分かるか

補助的に文長を機械集計した。句点等による概算では約2,190文のうち、95字以上が約312文、120字以上が約135文だった。これは品質判定そのものではなく、長文が局所例ではなく継続的に発生していることを確認するシグナルとして用いた。

## 結論

史実・用語説明の水準は高校生向けの前提を概ね満たしている。一方、文章の組み立ては一部で大学受験向け概説に近づき、**「理解できるが、無理なくは読めない」**箇所が増えている。

主因は難語そのものではなく、以下の五類型だった。

### A. 抽象語が具体的な主体・行為より先に出る

例として、「外交回路」「政策分岐」「制度回路」「国家意思決定」「制度状態」などが段落の入口に置かれると、読者は語の意味を展開してから史実へ戻る必要がある。

改善方針は、先に「野村・来栖は会談を続けた」「政府は12月1日に開戦を決めた」「陸海軍は別の命令系統で作戦を進めた」と書き、その後に「外交回路が残った」「政策分岐が閉じた」とまとめること。

### B. 一文が複数の仕事をしている

1941年後半では、一文の中で「前期間の状態」「当日の決定」「制度上の意味」「次の帰結」を同時に処理する文が目立つ。内容は正しいが、読み手は主語・時点・結論を保持し続ける必要がある。

一文一情報へ機械的に切る必要はないが、中心動作または中心結果を一つに寄せる。前提と結果が別なら二文に分ける。

### C. 分析語が具体説明の代用品になる

「この構造が〜」「この制度回路が〜」「枠組みが〜」だけで前文全体を受けると、何を指すのかを読み返す必要がある。分析語は有用なので削除対象にはしない。

具体的な名詞へ一度戻し、「政府と統帥部が別の手続で動いた。この制度分担のため〜」のように、指示対象を明示してから抽象化する。

### D. 見出しが分析結果を先に言いすぎる

「〜が政策分岐を狭めた」「〜を制度段階へ変えた」のような見出しは、本文を読んだ後には明快だが、初見では何が起きた節なのか分かりにくい場合がある。

見出しは「11月26日 — ハル・ノートが提示された」のような具体的出来事を足場にし、必要ならダッシュ以後で分析的意味を添える。

### E. 高校用語の説明不足より、説明密度の高さが問題

「御前会議」「大本営政府連絡会議」「統帥」「ハル・ノート」などは、定着語を残したうえで役割を説明できている記事が多い。したがって、可読性改善の中心を難語置換へ置くべきではない。

むしろ、定着語を避けて抽象的な言い換えへ置換すると、かえって高校生の学習導線を壊す。必要語は残し、周囲の文を具体化・短文化する。

## 時期別所見

### 7〜9月

制度・経済制裁・首脳会談の説明は比較的具体的。資産凍結や石油輸出管理では仕組みの説明が先にあり、分析へ進む段落が多い。

一方、9月に「外交と戦争準備を並行させる枠組み」「政策時計」などの圧縮表現が増え始める。

### 10月

東条内閣成立と国策再検討で扱う制度主体が増え、「意思決定回路」「入力値」「外部条件」のような分析語が増える。内容の整理には有効だが、段落冒頭では具体的な会議・発言・決定を先に置く方が読みやすい。

### 11月後半〜12月8日

最も硬さが強い。外交、統帥、通信、宣戦手続を同時に扱うため、「外交回路」「制度段階」「国家意思決定」「複数の制度回路」などが本文の圧縮語として頻出する。

この範囲は分析内容を削るのではなく、**具体的出来事 → 制度上の仕組み → 分析上の意味**へ並べ直すだけで改善余地が大きい。

## 採用する執筆規則

CONTENT_AUTHORING_STANDARD.md に以下を追加する。

- 具体 → 仕組み → 抽象を標準順序とする
- 分析語は具体説明の要約として使い、代用品にしない
- 一文の中心動作・中心結果を一つに寄せる
- 100字前後を超える文や、固有名詞・制度名・読点が多い文は人間レビュー上の分割候補とする
- summary・見出し・中心問いも具体的出来事を足場にする
- 重要な定着語を易しい言い換えで消さない

SYSTEM_PROMPT.md には重複を避け、常時必要な「具体 → 仕組み → 抽象」と、分析語を具体説明の代わりにしない原則だけを短く反映する。

## CI方針

現段階では「90字超なら失敗」「抽象語がN回なら失敗」のようなhard CIは導入しない。史料名・正式名称・必要な制度説明まで壊しやすく、可読性は文長だけでは判定できないためである。

将来の負債検出では、文長、抽象語密度、段落冒頭の分析語、同一文中の固有名詞数などを**warning候補抽出**に使い、人間レビュー対象を絞る。基準が安定してから、機械判定できる狭いパターンだけをCI化する。
